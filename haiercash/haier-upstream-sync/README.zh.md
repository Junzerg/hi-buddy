# 海尔上游同步工作流程

[English](README.md) | 中文

## 概述

本流程面向公司分支维护者：吸收上游能力和修复，保留定制清单中已确认的公司产品行为。允许调整实现方式；改变产品要求需要记录明确决策。

## 文档与版本

[定制保留清单](local-customizations.zh.md)描述当前公司要求。`records/` 下每份文件记录一次同步，参见[当前 rc.1 记录](records/2026-11-05-rc.1.zh.md)与[先前 alpha.3 评估](records/2026-11-03-alpha.3.zh.md)。这些内部文档不加入公开文档网站。

流程和清单通过 Git 提交管理版本，不另存 v1/v2 副本。清单使用稳定的 `HAIER-xxx` 编号。定制变更时，同步更新行为、代码入口与验收要求；废止要求需明确标记，编号不复用。

每次记录包含状态、本地分支与起点 SHA、共同祖先、上游标签及解析后的 SHA、采用的清单提交、集成分支、按定制编号归属的决策、检查结果、未完成项和最终合并提交。清单提交生成后再登记，不能预填文档自身的提交号。

上游基线版本与内网发布版本分别记录。发布标签和分发规则以[内网发布参考](../../apps/desktop/packaging/INTRANET.md)为准；完成代码合并不代表完成发布。

## 同步步骤

按批次交互式推进：基线与隔离环境、元数据与依赖及语言、核心与 IAM、桌面与内网分发、逐区域 UI、综合验收与合回。每批先明确范围，完成后交付处理结果、验证证据和未决事项；用户确认后才进入下一批。仅完成预演不算开始解决冲突，未具备运行条件的检查标记为待验证。

1. 检查工作区并更新远程引用。`dev/junzerg` 是内网主推进分支；其他 `dev/*` 分支另行确认范围，`origin/master` 和非 `dev/*` 分支可按需参考或合并。保留无关工作。

2. 固定本地起点、上游目标和清单版本。阅读上游发布及升级说明，关注数据格式、配置、插件依赖和 UI 功能入口。预演合并并分类实际冲突。

3. 从固定本地起点创建 `integrate/haier-upstream-<target>` 分支及独立 worktree，在其中合并固定目标。保留上游祖先关系，不压缩上游合并，也不以常规零散 cherry-pick 替代整体同步。

4. 依次处理元数据与依赖、运行时与企业集成、各 UI 区域。自动合并的关键路径也要检查。特殊取舍和暂缓接入的上游能力必须记录影响。

5. 按[测试策略](../../docs/testing.zh.md)选择受影响检查，双向验证上游能力与公司要求。UI 每处理一个区域，提供可运行预览或截图，交付审阅后再进入下一区域。

6. 落地前重新检查 `dev/junzerg`。若已有新提交，将其纳入集成并重跑受影响检查。遵循[推送前检查](../../.agents/skills/dsh-pre-push-checks/SKILL.md)，保留合并历史并补全记录。发布作为独立任务执行。

<a id="conflicts"></a>

## 冲突处理规则

| 区域 | 规则 |
|---|---|
| 核心能力与接口 | 吸收上游演进并适配本地调用；暂缓接入的能力需记录。 |
| UI | 保留已确认的视觉与交互要求，接入新逻辑、无障碍支持和缺陷修复。 |
| 品牌 | 在上游当前的文案归属位置保留公司品牌；技术标识和兼容标识未经明确迁移不改名。 |
| IAM 与内网分发 | 保留公司约束，适配上游生命周期变化。 |
| 语言 | 保留支持语言范围并更新新增文案；检查上游新增语言资源。 |
| 依赖与生成文件 | 先解决源配置，再通过仓库工具重新生成。 |

禁止全局采用“全部本地”或“全部上游”策略。文件路径用于定位，不代表永久归属：上游可能把行为搬到其他包。文本无冲突不代表行为兼容。

<a id="acceptance"></a>

## 验收与恢复

验收覆盖会话创建与历史、消息发送与取消、工具执行及本次升级涉及的上游能力，同时覆盖适用的定制编号。记录实际命令、环境、结果与人工验收证据。不得仅为消除失败而刷新快照。

未解决的核心功能回归或缺少证据的必要检查会阻止落地。无关失败单独记录并判断是否阻断本次集成，不自动扩大修复范围。

落地前保留原分支，在保存有用工作后放弃或修复隔离集成环境。落地后通过审阅的回退提交或后续修复处理，不改写共享历史。代码回退不会撤销数据迁移；新构建接触重要用户数据前，单独验证数据兼容性。部署回退遵循内网发布参考。

<a id="lessons"></a>

## rc.1 同步经验

- **区分上游跟踪与公司交付。** 将上游全部分支抓取到 `upstream/*`；确认本地没有独有提交并建立备份后，再同步本地 `master`。Fetch 不会更新本地分支或 `origin`。通过独立 worktree 将固定发布版本合入 `dev/junzerg`，不得中途默默换成更新的 master。
- **保留行为，而非整份文件。** 即使上游迁移实现位置，公司配色、布局、交互、IAM 和隐藏入口仍是验收依据。可选能力可以合入代码，但不启用 bundle、不开放入口。本次保留了 CUA 代码，其 macOS provider 保持关闭；Linux 无法验证原生权限流程。
- **以批次作为审阅边界。** 每批从已确认的小范围开始，明确未决事项，交付可审阅结果后停下。记录原则和特殊取舍，不逐条抄录确认对话。用户选择集中人工验收时，记录该选择，不重复要求局部预览。
- **在最终推送前提前执行集成检查。** 冲突标记清零只是第一步。运行时代码编译、测试整体类型、生成目录、双语记录、文档检查和全量 lint 都可能分别失败。输入就绪后各执行一次，针对失败范围修复，复用仍有效的结果。界面预览成功不能替代这些检查。
- **先诊断浏览器失败，再更新预期。** 旧快照可能保留已隐藏的上游入口，或遗漏公司界面元素。逐项审阅实际采集差异，再执行只读回放。公司会话行较紧凑，测试必须预置足够会话形成真实溢出，不能删除溢出断言。只检查空白首页时，不挂载不会消费的模型回放。控件定位使用公司实际的无障碍名称。
- **显式衔接并行修改与仓库更名。** 合回前备份主工作区的暂存与未暂存修改。公司后续改动单独提交，再接入集成结果，不能覆盖上游版本号。`lingxi-office` 更名为 `hi-buddy` 还影响工作区身份识别及 Git hooks 绝对路径；两个 worktree 都需重新安装 hooks 并验证依赖安装，不因本地目录更名顺带修改内网部署路径。
- **区分回滚准备与交付阶段。** 为原始基线、合并前公司状态、固定上游、集成结果和合回结果保留分支；未提交补丁与合并索引备份保存在源码之外。推送后采用审阅过的回退提交或后续修复，不重置共享历史。分别记录冲突处理、本地合回、Web 验收、远端推送、安装包验收和内网发布。模拟器上的 Web 验收不代表真实 IAM、模型输出、全新安装或增量更新通过。

[rc.1 记录](records/2026-11-05-rc.1.zh.md)保存实际提交、完成状态及剩余平台验收项。同步记录允许保留用于回滚的准确提交号；该例外不放宽禁用链接检查，也不适用于其他文档。
