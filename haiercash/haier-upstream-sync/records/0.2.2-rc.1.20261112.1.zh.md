# HiBuddy 0.2.2-rc.1.20261112.1

[English](0.2.2-rc.1.20261112.1.md) | 中文

## 概述

[已确认的打包记录](0.2.2-rc.1.20261112.1.json)为 Windows x64 未签名包和 Mac arm64 签名公证包固定源码 `02b9f663183f703d003637407027c980a1ca3015`。两端独立构建版本 `0.2.2-rc.1.20261112.1`，共同发布。此版本两端均未开始构建，全部产物与安装验收字段仍待完成。切换[当前指针](../current-desktop-build.json)前已确认上一版构建均已停止或完成。

## 两端分别打包

遵循[打包交接指南](../desktop-packaging.zh.md)及其中的联合发布协作规则。Windows 安装包为 `HiBuddy-0.2.2-rc.1.20261112.1-win-x64-unsigned.exe`，服务器归档为 `lingxi-office-release-0.2.2-rc.1.20261112.1.tar.gz`。Mac 安装包为 `HiBuddy-0.2.2-rc.1.20261112.1-mac-arm64.dmg`，服务器归档为 `lingxi-office-release-0.2.2-rc.1.20261112.1-mac-arm64.tar.gz`。保留同批 feed、blockmap、构建记录及已签名 Mac ZIP。每台机器仅更新本平台状态、实际源码与工作区干净证据、安装包大小与哈希、归档哈希、适用的签名证据及安装验收，保留另一平台结果。

## 公司登录服务前置条件

本版本直接从 `getOrCreate.data.models` 初始化 IAM 模型配置。`isMultimodal: true` 在 dsh 中转换成 `input: [text, image]`，false 则为纯文本输入；模型选择器根据实际生效的能力显示“多模态”标签。IAM 完成流程不调用 `/models`，手动 API Key 登录仍保留模型发现。

两端验收登录前，先部署同一源码提交中的 company-login 交换服务，让 `/company-login/exchange` 的 `models` 响应包含已授权的 `modelName`、布尔值 `isMultimodal` 及可选的正整数 `contextLength`。旧交换服务缺少这些资料，无法完成本版本客户端的 IAM 登录。按[交换服务部署流程](../../../apps/desktop/packaging/README.zh.md#company-login)操作，保留现有服务端密钥及无关路由，将实际部署与验证结果记入 `serverPrerequisites.companyLogin`。内网操作人员提供证据前，该状态保持待完成；本开发机无法访问该服务器。

## 重新验收与联合发布

在两端安装后的应用中退出并重新登录，验证授权模型列表、“多模态”标签、图片预览，并向标记为支持图片的模型发送图片。网关必须收到图片内容并返回与图片相关的回答，仅保存标记、显示标签或得到泛泛的成功回答都不算通过。纯文本模型须继续拒绝图片输入。同时验证启动、升级、文本对话、内网搜索与抓取、内置 Claude、Office 预览及重启后的数据保留。此前的黑色预览未宣称已修复，须在两端明确验收。

本地证据覆盖 138 项相关单元测试、18 项模拟器测试、新增公司模型浏览器场景、Host／Client 类型检查、Client bundle 和 Web 构建；3 项内网发布测试验证实际平台归档生成及 Windows／Mac 目录合并。另有 3 项既有模型徽标浏览器断言要求的徽标与名称顺序同源码相反，不作为通过证据。任何本地结果都不能代替 Windows 或 Mac 安装验收。

只有两端均验证通过、交换服务前置条件也已验证，并取得单独发布授权后，交接负责人才可发布。将两份已验证的平台归档合入同一份从线上继承的服务器目录，保留两份新目录数组及历史记录，验证两端后只切换一次，再记录线上验证结果。任一平台、服务端前置条件或线上验证未完成时，保持 `published: false`。任一端开始后，不得改变源码或目标模式；源码变更须重新确认新版本。
