# 演示文档 A：文档库检索验证笔记

> 用途：用于验证 HiBuddy 文档库的分块索引、关键词检索与分页读取。
> 关键词（刻意重复，便于测检索命中）：`doclib`、`演示`、`分块`

## 1. 这份文档要验证什么

演示文档不是产品资料，它存在的唯一目的是给文档库提供一个可控的输入。用它可以检查三件事：

1. **索引是否覆盖工作区文件** —— 新建的 `.md` 是否能在 `doc_search` 中命中；
2. **中文检索是否按二元组切分** —— 输入“文档库”“分块”这类词能否命中相邻片段；
3. **分页读取是否边界正确** —— 用 `offset` / `maxChars` 翻页时是否不丢字、不重字。

## 2. 背景：为什么需要演示文档

文档库同时索引两类实体：

| 实体类型 | 存放位置 | 修改方式 |
| --- | --- | --- |
| 工作区文件 | 仓库内的普通路径 | 直接编辑，索引下次刷新生效 |
| 上传附件 | 内容寻址的 blob 仓库 | 只读，需另存到工作区才能改 |

前一类可以随时改，适合做试验田；后一类是快照，适合做对照基准。演示文档刻意选择前一类。

## 3. 结构约定

为了让切块器有活可干，本文按下面几条约定组织：

- 每节标题不少于两级，`##` 用于小节，`###` 用于子话题；
- 每节正文控制在 3 段以内，避免单块过大；
- 至少保留一个表格、一段代码、一个列表，覆盖不同块类型；
- 关键术语在首次出现处加粗，便于观察命中标注。

### 3.1 一个小代码块

```python
def chunk_markdown(text: str, limit: int = 800) -> list[str]:
    """按空行切段，再按长度合并到 limit 以内。"""
    blocks = [b.strip() for b in text.split("\n\n") if b.strip()]
    chunks, buf = [], ""
    for block in blocks:
        if len(buf) + len(block) > limit and buf:
            chunks.append(buf)
            buf = block
        else:
            buf = f"{buf}\n\n{block}" if buf else block
    return chunks + ([buf] if buf else [])
```

这段伪代码只说明分块的直觉：先按语义段切，再按长度聚合。真实实现还要处理标题边界与代码围栏。

### 3.2 一个检查清单

- [ ] 文档已保存为 UTF-8，末尾仅一个换行
- [ ] 标题层级连续，不跳级
- [ ] 表格列数一致
- [ ] 代码块标注了语言
- [ ] 文中未出现未闭合的强调标记

## 4. 预期结果

写入完成后，用下面的查询验证：

1. 搜 `演示` —— 应命中本文多处；
2. 搜 `分块` —— 应命中第 1 节与第 3 节；
3. 搜 `chunk_markdown` —— 应命中代码块所在片段；
4. 搜 `不存在的词条 xyz` —— 应返回空结果而不是报错。
